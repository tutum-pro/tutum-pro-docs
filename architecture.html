architecture Platform Architecture

account_tree High-Level Architecture

The Tutum Platform follows a layered microservices architecture with clear separation of concerns. For Kubernetes certificate distribution, the platform supports two modes: Operator (CRD-based, rootless, recommended) and CSI Driver (volume-based, legacy, privileged).

info
Kubernetes Injection Modes:
  • Operator Mode (Recommended): Syncs certificates to Kubernetes Secrets via TutumCertificate CRD. Rootless, OpenShift-compatible (restricted-v2 SCC).
  • CSI Driver Mode (Legacy): Mounts certificates as CSI ephemeral volumes. Requires privileged containers (DaemonSet).

🎯 Operator Mode (Recommended)
  • Rootless: No privileged containers required
  • Native: Uses standard Kubernetes Secrets
  • Declarative: TutumCertificate CRD
  • Auto-sync: Kubelet updates volumes automatically (~60s)
  • OpenShift: Compatible with restricted-v2 SCC
  • Lightweight: Single deployment (not per-node)
⚠️ CSI Driver Mode (Legacy)
  • Privileged: Requires escalated permissions
  • Direct mount: CSI ephemeral volumes
  • Pod restart: Required for certificate updates
  • DaemonSet: Runs on every cluster node
  • Use case: Legacy deployments only
  • OpenShift: Requires privileged SCC

api API Architecture

Dual API Design

Tutum implements a dual-API architecture for different use cases:

API Type Protocol Port Use Case Security
REST API HTTP/JSON 8080 Administration & Management JWT Authentication
gRPC API Protobuf v3 9090 Certificate Retrieval mTLS (recommended)

REST API Endpoints

30+ RESTful endpoints for complete certificate lifecycle management:

  • POST /api/v1/certificates - Create certificate
  • GET /api/v1/certificates - List certificates with filters
  • GET /api/v1/certificates/:name - Retrieve certificate
  • PUT /api/v1/certificates/:name - Update certificate
  • DELETE /api/v1/certificates/:name - Delete certificate
  • GET /api/v1/certificates/expiring - Find expiring certificates
  • POST /api/v1/groups - Create certificate group
  • POST /api/v1/namespaces - Create namespace
  • POST /api/v1/channels - Create distribution channel
  • POST /api/v1/channels/:id/tokens - Create access token

gRPC Services

Protocol Buffer-defined services for efficient certificate retrieval:

  • CertificateService - GetCertificate, ListCertificates, WatchCertificate, GetCertificateMetadata
  • GroupService - CreateGroup, GetGroup, ListGroups, UpdateGroup, DeleteGroup

Envelope Encryption

Three-tier encryption architecture for maximum security:

  1. Master Key (32 bytes) - Loaded from TUTUM_MASTER_KEY environment variable
  2. Data Encryption Keys (DEKs) - Random 256-bit keys generated per certificate
  3. Certificate Private Keys - Encrypted with DEK using AES-256-GCM
warning
Security Best Practice: Never commit the Master Key to version control. Use different keys for each environment (dev, staging, production).

  • mTLS for gRPC - Mutual TLS authentication for certificate retrieval

  • TLS 1.3 - Modern TLS protocol support

deployed_code Deployment Models

Kubernetes Deployment

  • tutum-engine: Deployment with RollingUpdate strategy
  • tutum-csi-driver-k8s: DaemonSet on all nodes
  • CSIDriver CRD: Custom Resource Definition for driver registration
  • StorageClass: Dynamic volume provisioning

Docker Deployment

  • tutum-engine: Docker Compose with PostgreSQL container
  • tutum-csi-driver-docker: Systemd service (recommended) or Docker plugin
  • Plugin Discovery: Via /etc/docker/plugins/*.spec files

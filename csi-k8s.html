cloud Kubernetes CSI Driver (tutum-csi-driver-k8s)

Container Storage Interface Driver for Kubernetes - Native Certificate Volume Mounting

info Overview

tutum-csi-driver-k8s is a Kubernetes CSI (Container Storage Interface) driver that enables pods to mount X.509 certificates as volumes. Certificates are retrieved from tutum-engine and exposed as files in a tmpfs filesystem.

security
Security: Certificates are stored in memory (tmpfs), never written to disk, and automatically cleaned up when pods are terminated.

Deploy CSI Driver

# Apply all CSI driver manifests
kubectl apply -f deploy/k8s/

# Verify Controller and DaemonSet are running
kubectl get pods -n tutum-system -l app.kubernetes.io/name=tutum-csi-driver

# Check CSI driver registration
kubectl get csidriver csi.tutum.io

# Verify StorageClass
kubectl get storageclass tutum-csi

play_arrow Usage

1. Create StorageClass

apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: tutum-csi
provisioner: csi.tutum.io
parameters:
  # Tutum Engine gRPC URL (required)
  engineUrl: "tutum-engine.tutum-system.svc.cluster.local:9090"
volumeBindingMode: Immediate
reclaimPolicy: Delete
info Note: The engineUrl parameter specifies which tutum-engine instance to connect to. This allows multiple engines per cluster with different StorageClasses.

2. Create PersistentVolumeClaim

apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-app-cert
  namespace: production
  annotations:
    # Certificate parameters
    certificateName: "my-app-cert"
    groupID: "production-group-uuid"
    namespace: "production"           # Tutum certificate namespace
    channel: "internal"               # Optional: distribution channel
    authToken: "secret-token"         # Optional: for protected channels
spec:
  storageClassName: tutum-csi
  accessModes:
    - ReadOnlyMany
  resources:
    requests:
      storage: 1Mi

3. Mount in Pod

apiVersion: v1
kind: Pod
metadata:
  name: my-app
  namespace: production
spec:
  containers:
    - name: app
      image: my-app:latest
      volumeMounts:
        - name: cert-volume
          mountPath: /etc/ssl/certs/my-app
          readOnly: true
  volumes:
    - name: cert-volume
      persistentVolumeClaim:
        claimName: my-app-cert

Mounted Files

/etc/ssl/certs/my-app/
├── tls.crt          # Certificate (PEM)
├── tls.key          # Private key (PEM)
├── ca.crt           # CA chain (PEM)
└── metadata.json    # Certificate metadata

flash_on Inline Ephemeral Volumes

For simpler use cases, use CSI inline ephemeral volumes without PVC:

Single Certificate Mode

apiVersion: v1
kind: Pod
metadata:
  name: my-app
spec:
  containers:
    - name: app
      image: my-app:latest
      volumeMounts:
        - name: cert
          mountPath: /etc/ssl/certs/my-app
          readOnly: true
  volumes:
    - name: cert
      csi:
        driver: csi.tutum.io
        readOnly: true
        volumeAttributes:
          engineUrl: "tutum-engine.tutum-system.svc.cluster.local:9090"
          certificateName: "my-app-cert"
          groupID: "production-group-uuid"
          namespace: "production"

Tree Mode (All Certificates with Name)

Omit groupID and namespace to mount all certificates with the given name from all groups/namespaces:

volumes:
  - name: all-certs
    csi:
      driver: csi.tutum.io
      readOnly: true
      volumeAttributes:
        engineUrl: "tutum-engine.tutum-system.svc.cluster.local:9090"
        certificateName: "tls-cert"
        # Tree structure: /mount-path/namespace/groupID/
warning Important: For ephemeral inline volumes, you must provide engineUrl in volumeAttributes since StorageClass parameters are not used.

settings Configuration

Volume Attributes

AttributeRequiredDescription
engineUrlYes*Tutum Engine gRPC URL (required for ephemeral volumes)
certificateNameYesCertificate name
groupIDNo**Group UUID (omit for tree mode)
namespaceNo**Tutum certificate namespace (omit for tree mode)
versionNoSpecific version number (default: latest)
channelNoDistribution channel name (default: "default")
authTokenNoAuthentication token for protected channels
fileUidNoFile owner UID (default: 0)
fileGidNoFile owner GID (default: 0)
secretExtensionNoExtension for secret files (default: ".txt")

* Required for ephemeral inline volumes; for PVC volumes, engineUrl comes from StorageClass.
** For single certificate mode, both groupID and namespace are required. Omit both for tree mode.

Driver Command Line Arguments

ArgumentDefaultDescription
--endpointunix:///csi/csi.sockCSI socket endpoint
--nodeid(required)Kubernetes node name
--tutum-engine-url(empty)Default Tutum Engine URL (optional fallback)
--use-tlsfalseEnable TLS for engine connection
--tls-certTLS certificate file path
--tls-keyTLS key file path
--tls-caTLS CA certificate file path
info Note: The --tutum-engine-url argument is optional. When provided, it serves as a default fallback for volumes that don't specify engineUrl in their attributes. The preferred approach is to specify engineUrl in StorageClass parameters.

# Check DaemonSet pods
kubectl get pods -n tutum-system -l app=tutum-csi-driver

# View driver logs
kubectl logs -n tutum-system -l app=tutum-csi-driver -c csi-driver

# Check CSI driver registration
kubectl get csidriver tutum.io -o yaml

# Describe CSI node info
kubectl get csinodes -o yaml

Common Issues

Verify the certificate exists and the group/namespace match:

curl http://tutum-engine:8080/api/v1/certificates?group=GROUP_ID&namespace=NAMESPACE

Ensure the auth token secret exists and contains a valid token:

kubectl get secret tutum-token-secret -o yaml
kubectl describe secret tutum-token-secret

Check network connectivity and DNS resolution:

# From CSI driver pod
kubectl exec -n tutum-system tutum-csi-driver-xxx -- nslookup tutum-engine
kubectl exec -n tutum-system tutum-csi-driver-xxx -- nc -zv tutum-engine 9090
